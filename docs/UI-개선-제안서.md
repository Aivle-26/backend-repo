# UI 개선 제안서 — "좀 더 심플한 화면 구성"

> 상태: **설계/기획 단계 (구현 미착수)** · 승인 후 구현 시작
> 대상: BidWorks AI (AI 협업 리스크 관리 / RFP 프로젝트 관리), PM · 직원 화면

---

## 1. 현재 UI의 문제점

### 메뉴가 너무 많고 잘게 쪼개져 있음
PM 8개(대시보드 · 공고문 업로드 · AI 분석 · 요구사항 · 업무 배정 · 문서 통합 관리 · 리스크 · 검토), 직원 7개(내 업무 · RFP 맥락 · 문서 통합 관리 · 리스크 · 산출물 제출 · 피드백 · 댓글). 처음 보는 사용자는 "AI 분석 / 요구사항 / 업무 배정"이 뭐가 다른지, "RFP 맥락"이 뭔지 알기 어렵습니다.

### 같은 흐름이 여러 페이지로 흩어짐
- PM의 `공고문 업로드 → AI 분석 → 요구사항 → 업무 배정`은 사실 하나의 연속된 작업인데 4개 메뉴로 분리돼, 오갈 때마다 맥락이 끊깁니다. 게다가 `AI 분석`·`요구사항`·`업무 배정`은 모두 "요구사항"을 다뤄 내용이 겹칩니다.
- 직원의 `산출물 제출 / 피드백 / 댓글`은 전부 "하나의 업무를 처리하는" 부분 화면인데 최상위 메뉴로 올라와 있습니다. 원래는 업무 상세 안에 있어야 할 것들입니다.

### 한 화면에 정보가 과적재됨 (시인성 저하)
- `PM 리스크` 페이지: KPI 4 + 탐지현황 + AI 코멘트 + 노동법 + 개인정보검사 + 영향도 + 인수인계 체크리스트 + 대응 액션 + 빠른 조치 = **한 화면에 8~9개 섹션**. 무엇부터 봐야 할지 판단이 안 됩니다.
- `PM 대시보드`: KPI + 업로드 드롭존 + AI 요약 + 요구사항 미리보기 + 팀 현황 + 리스크 + 협업 흐름까지 한 화면에 다 넣어 "요약"의 역할을 잃었습니다.

### PM/직원 화면이 개념은 같은데 따로 구현됨
문서 통합 관리, 리스크 화면이 역할별로 중복돼 있어 유지보수·일관성 부담이 큽니다.

### 네비게이션이 "작업 흐름"을 안 보여줌
업로드 → 분석 → 배정 → 수행 → 제출 → 검토라는 자연스러운 여정이 메뉴 순서/구조에 드러나지 않아, 지금 어디 단계인지 감이 안 옵니다.

## 2. 개선 방향

- **"할 일(Job) 단위"로 메뉴를 묶는다.** 기능 하나당 페이지 하나가 아니라, 사용자가 하려는 일 단위로 통합. PM 8 → **5**, 직원 7 → **4** (+ 업무 상세).
- **연속 작업은 한 워크스페이스 + 단계(탭)로.** 업로드~배정을 한 페이지에서 단계로 진행.
- **"개요 → 드릴다운" 원칙.** 밀도 높은 화면(리스크)은 요약 화면에서 핵심만 보여주고, 항목을 누르면 상세가 열리게. 한 화면에 다 펼치지 않음.
- **PM/직원 공통 컴포넌트화.** 문서 · 리스크 · KPI · 피드백/댓글 · 테이블을 role 프롭으로 공유.
- **일관된 페이지 골격.** 모든 페이지: `헤더(제목 + 주요 액션 + 필터) → 요약 스트립 → 본문(한 가지 초점) → 보조 패널`. 주요 버튼은 헤더 우상단 1개(primary)만.
- **라벨을 쉬운 말로.** "RFP 맥락" → 업무 상세 내 "관련 요구사항" 탭, "AI 분석" → "분석·배정"에 흡수.

## 3. 추천 전체 페이지 구조 (사이트맵)

```
로그인
│
├── PM 워크스페이스
│   ├── 1. 홈(대시보드)        ← 프로젝트 한눈에 + 오늘 할 일
│   ├── 2. 분석 · 배정          ← [업로드]→[요구사항]→[배정] 단계 통합
│   │        └ (요구사항 상세 드로어)
│   ├── 3. 리스크               ← 개요(요약) → 리스크 상세 드릴다운
│   ├── 4. 문서                 ← 문서 통합관리 + AI 챗봇
│   └── 5. 검토함               ← 제출물 승인/반려 (인박스형)
│
└── 직원 워크스페이스
    ├── 1. 홈(내 업무)          ← 업무 보드 + 오늘 할 일
    │        └ 업무 상세 (탭: 개요·관련 요구사항 / 산출물 제출 / 피드백·댓글)
    ├── 2. 리스크               ← 공통 리스크 화면(읽기 중심)
    ├── 3. 문서                 ← 공통 문서 화면
    └── 4. 알림/게시판(선택)     ← 팀 커뮤니케이션

공통 재사용: 사이드바 · 상단바 · KPI 스트립 · 데이터테이블(필터/탭) ·
            리스크 배지 · 문서리스트+챗봇 · 피드백/댓글 스레드 · 페이지헤더
```

핵심 변화
- 직원의 `산출물 제출 · 피드백 · 댓글` → **업무 상세의 탭**으로 흡수.
- PM의 `업로드 · AI분석 · 요구사항 · 업무배정` → **"분석·배정" 한 페이지의 단계**로 통합.
- 리스크는 **개요 + 상세**로 분할.

## 4. 각 페이지 핵심 기능

| 페이지 | 핵심 기능 | 흡수/변경 |
|---|---|---|
| **PM 홈** | 진행률·남은일수·고위험 3지표 · 오늘 할 일 · 상위 리스크 3 · [분석·배정 이어가기] | 업로드 드롭존·요구사항표·협업흐름 제거(각 페이지로) |
| **PM 분석·배정** | 단계 인디케이터(①업로드 ②요구사항 ③배정) 한 흐름 | 기존 4개 메뉴 통합 |
| **PM 리스크(개요)** | KPI 4 + 긴급 대응 리스트, 항목 클릭 시 상세 드로어 | 8~9개 섹션을 항목별 드릴다운으로 분리 |
| **PM 문서** | AI 생성 파일 + 자료실 연동 + AI 챗봇(우측 고정) | 유지 |
| **PM 검토함** | 제출 산출물 인박스, 승인/반려 + 피드백 | 라벨만 명확화 |
| **직원 홈** | 내 업무 칸반 + 오늘 마감/검토 대기 | 유지 |
| **직원 업무 상세** | 탭: 개요(설명·체크리스트·관련 요구사항) / 산출물 제출 / 피드백·댓글 | 3개 메뉴를 탭으로 통합 |
| **직원 리스크·문서** | PM과 동일 컴포넌트(읽기/본인 관련) | 공통화 |

## 5. 화면 와이어프레임 (텍스트)

### 공통 셸 (사이드바 축소)
```
┌──────────┬─────────────────────────────────────────────┐
│ ◆ 로고    │  페이지 제목            [주요 액션]  🌙 알림 👤 │
│          │─────────────────────────────────────────────│
│ ▸ 홈      │                                             │
│ ▸ 분석·배정│   (본문: 한 화면 = 한 가지 초점)              │
│ ▸ 리스크  │                                             │
│ ▸ 문서    │                                             │
│ ▸ 검토함  │                                             │
│  ──────  │                                             │
│ 👤 윤다영 │                                             │
└──────────┴─────────────────────────────────────────────┘
```

### PM 홈 (간소화)
```
프로젝트 A                                   [분석·배정 이어가기]
┌ 진행률 62% ┐ ┌ 남은 14일 ┐ ┌ 고위험 3 ┐
└───────────┘ └──────────┘ └──────────┘
┌── 오늘 할 일 ─────────────┐  ┌── 상위 리스크 ──────────┐
│ • 검토 대기 3건      →    │  │ 🔴 회원가입 SQL 주입      │
│ • 미배정 요구사항 5건 →   │  │ 🟠 결제 API 성능 저하     │
│ • 노동법 검토 1건    →    │  │ 🟠 개발 일정 노동법 검토  │
└──────────────────────────┘  └─────────────────────────┘
```

### PM 분석·배정 (단계 통합)
```
분석 · 배정
①업로드 ─────●───── ②요구사항 ────── ③배정
┌──────────────────────────────────────────────┐
│ [②요구사항]  🔎검색  분류▾ 우선순위▾           │
│ ┌───┬───────────────┬────┬──────┬────────┐    │
│ │ # │ 요구사항       │분류│우선  │추천담당│    │
│ │ 1 │ 비상 조명 …    │안전│ 높음 │ 김지훈 │ →  │  ← 행 클릭 시 상세 드로어
│ └───┴───────────────┴────┴──────┴────────┘    │
│                         [뒤로] [③ 배정으로 →] │
└──────────────────────────────────────────────┘
```

### PM 리스크 (개요 → 상세 드릴다운)
```
리스크                                          [새 리스크]
┌ 전체 8 ┐ ┌ 긴급 2 ┐ ┌ 법·검토 3 ┐ ┌ 영향 +4일 ┐
└────────┘ └────────┘ └──────────┘ └───────────┘
┌── 긴급 대응 필요 ───────────────────────────┐
│ 🔴 개인정보 포함 회의록      보안    미조치  →│──┐
│ 🟠 결제 기능 범위 변경       일정    분석완료→│  │ 클릭
│ 🟠 Backend 담당자 교체       인수인계 진행 → │  │
└─────────────────────────────────────────────┘  │
        ▼ (우측 드로어로 상세만 표시)              │
   ┌─ 리스크 상세: 개인정보 회의록 ────────────┐ ◀┘
   │ 개인정보검사 2건 · 심각도 높음            │
   │ 권장조치: 마스킹 / 접근권한 축소          │
   │ [문서 마스킹 적용]  [담당자 알림]         │
   └───────────────────────────────────────────┘
```

## 6. 개선 우선순위

| 순위 | 내용 | 비고 |
|---|---|---|
| **P0** | 직원 `제출·피드백·댓글` → 업무 상세 탭으로 흡수(메뉴 7→4) · 라벨 정리 | 효과 크고 리스크 낮음, 컴포넌트 이미 존재 |
| **P1** | PM `업로드·AI분석·요구사항·업무배정` → "분석·배정" 단계형 1페이지 통합(메뉴 8→5) | |
| **P2** | 리스크 페이지 "개요 + 상세 드릴다운"으로 분할 | 밀도 완화 |
| **P3** | 홈/대시보드 슬림화 + 문서/리스크 공통 컴포넌트 리팩터링 | |
| **P4 (선택)** | 홈에 진행 추세 미니차트, 알림/게시판 통합 | |

각 단계는 기존 기능을 **삭제 없이 재배치**하는 방향이라, 승인 시 P0부터 점진 적용하면 리스크가 적습니다.
