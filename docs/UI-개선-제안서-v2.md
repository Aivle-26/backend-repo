# UI 개선 제안서 v2 — 프로젝트 생애주기 중심 재구성

> 상태: **설계/기획 (구현 미착수)** · 조장님 피드백 + 결정사항 반영
> 핵심 전환: "기능 나열" → **"프로젝트 생애주기(목록 → 준비 마법사 → 진행)"**

---

## 0. 확정된 결정사항

1. **초기 문서 종류**: RFP · 요구사항정의서 · 제안서 (업로드 시 문서 타입 선택)
2. **프로젝트 상태 모델**: 분석중 · 준비 · 승인대기 · 진행중 · 완료 (승인)
3. **준비 마법사**: ① 요구사항 → ② WBS → ③ 담당자 → ④ 일정 → ⑤ 노동법·기업가이드 → ⑥ 견적 (순차)
4. **홈(대시보드)**: 여러 프로젝트를 카드로 보여주고, **이름 클릭 → 상세**, **[＋ 새 프로젝트]** 버튼. 예쁘고 편리하게.
5. **2사 승인 주체**: 보류 (추후 결정) — 일단 "승인대기" 상태 자리만 마련

---

## 1. 프로젝트 상태 전이도

```
[＋새 프로젝트]
   │  초기 문서 업로드(RFP·요구사항정의서·제안서)
   ▼
 분석중 ──AI 요구사항 추출──▶ 준비 ──마법사 ①~⑥ 완료──▶ 승인대기 ──▶ ▶시작 ──▶ 진행중 ──▶ 완료
                              │  (PM 요구사항/계획 수정)      (2사 검토·승인)
                              └ 목록에서 [수정][삭제] 가능
```

- **진행중** 프로젝트만 "운영 대시보드(KPI·오늘 할 일·리스크)"를 가짐.
- **분석중/준비/승인대기**는 홈 카드 + 준비 마법사에서 다뤄짐.

## 2. 사이트맵 v2

```
로그인
└── 홈 (프로젝트 보드)  ← 진입점. 여러 프로젝트 카드
    │   • 상태 필터(전체/준비/승인대기/진행중/완료) · 검색
    │   • [＋ 새 프로젝트]
    │   • 카드: 이름(클릭→상세) · 상태 · 요약 · [수정][삭제][▶시작]
    │
    ├── 새 프로젝트  (문서 업로드 → AI 추출 → '준비'로 생성)
    │
    ├── 프로젝트 상세  (카드 이름 클릭 시)
    │   ├─ 준비/승인대기 → 준비 마법사 열림
    │   │     ① 요구사항 ② WBS ③ 담당자 ④ 일정 ⑤ 노동법·가이드 ⑥ 견적 → [▶시작]
    │   └─ 진행중 → 운영 대시보드
    │         └ 탭/서브: 개요 · 요구사항 · 문서 · 리스크 · 검토 (프로젝트 컨텍스트)
    │
    └── (직원 워크스페이스는 기존 유지 — 내 업무/문서/리스크)
```

핵심: 지금의 최상위 메뉴(요구사항·업무배정·리스크·검토가 따로)가 **프로젝트 상세 안의 흐름/탭으로 흡수**됩니다.

## 3. 각 화면 구성

### 3-1. 홈 (프로젝트 보드)
- 프로젝트 카드 그리드. 상태별 색 배지.
- 카드 정보: 이름 · 상태 · (진행중이면) 진행률·마감·리스크 / (준비면) 마법사 진행 N/6 · 견적.
- 액션: 이름 클릭 → 상세 / [수정] [삭제] / [▶ 시작] (준비 완료 시에만 활성).
- 상단: 상태 필터 탭 + 검색 + **[＋ 새 프로젝트]**.

### 3-2. 새 프로젝트 (문서 업로드 → AI 추출)
- 초기 문서 여러 개 업로드. 각 문서 **타입 선택: RFP / 요구사항정의서 / 제안서**.
- [AI 요구사항 추출] → 추출 결과 미리보기(요구사항 N건) → [프로젝트로 생성] → 목록에 **준비** 상태로 등장.

### 3-3. 준비 마법사 (① ~ ⑥, 단계별 독립 페이지)
- 상단 스텝바(①~⑥, 현재 단계 강조), 하단 [이전] [저장] [다음].
- 각 단계 = **좌: AI 추천 결과 / 우: PM 수정 컴포넌트** 2단.
- 단계:
  1. **요구사항 확정** — AI 추출 목록 + PM 추가/삭제/우선순위.
  2. **WBS** — AI가 요구사항→작업 분해 + PM 편집.
  3. **담당자 배치** — AI 추천 + 팀 워크로드 + PM 조정.
  4. **일정 계획** — AI 간트/마일스톤 추천 + PM 조정.
  5. **노동법·기업가이드 검토** — AI 체크리스트(주52h 등) + PM 확인.
  6. **견적 산출** — AI 예상 견적 + PM 조정.
- 6단계 모두 완료 → **[▶ 프로젝트 시작]** 활성 → 진행중 전환.

### 3-4. 진행중 프로젝트 상세 (운영 대시보드)
- KPI(진행률·남은 일수·고위험) + 오늘 할 일 + 상위 리스크.
- 서브 탭: 요구사항 / 문서 / 리스크 / 검토 (모두 이 프로젝트 컨텍스트).

## 5. 기존 화면 재활용 매핑 (대부분 재배치)

| v2 위치 | 재활용할 현재 컴포넌트 |
|---|---|
| 홈 프로젝트 카드 | 신규(카드 UI) |
| 새 프로젝트 업로드 | `PmUpload`(드롭존/파일목록) 확장 + 타입 선택 |
| ① 요구사항 | `PmRequirements` + `PmAnalysis`(AI추출) |
| ② WBS | 문서 통합관리 WBS 산출물 로직 |
| ③ 담당자 | `PmAssign` (팀 워크로드 그대로) |
| ④ 일정 | MC 일정/간트 데이터 |
| ⑤ 노동법·가이드 | 현재 `PmRisk`의 노동법/기업가이드 섹션 |
| ⑥ 견적 | 현재 `PmRisk`의 예상 견적 섹션 |
| 진행중 리스크/문서/검토 | 기존 `PmRisk`/`PmDocuments`/`PmReview` |

> 지금 `PmRisk` 한 화면에 8~9개로 뭉쳐 있던 요소가 **마법사 단계로 분산** → 조장님이 지적한 "요구사항 30개면 한 화면에 다 못 넣음" 문제도 함께 해결.

## 6. 구현 우선순위 (승인 후)

| 순위 | 내용 |
|---|---|
| **P0** | 프로젝트 상태 모델 + 홈(프로젝트 보드: 카드·필터·검색·새 프로젝트) + 라우팅 |
| **P1** | 새 프로젝트(문서 3종 업로드 → AI 추출 스텁 → '준비' 생성) |
| **P2** | 준비 마법사 스캐폴드(스텝바 + ①~⑥ 페이지, 기존 컴포넌트 이식) |
| **P3** | [▶시작] 전이 → 진행중 상세(운영 대시보드 + 서브탭) |
| **P4** | 승인대기 / 2사 승인 흐름 (#5 결정 후) |

각 단계는 기존 기능을 **삭제 없이 재배치**하는 방향 → 리스크 낮음. P0부터 점진 적용 권장.

## 7. 남은 결정 (#5, 보류)

- 2사(발주사) 승인을 **외부도 이 툴에서** 하는지, PM이 대리 처리만 하는지.
  → "승인대기 → 진행중" 전이 UI/권한이 달라짐. 정해지면 P4에 반영.
